# Security Policy

## Supported Version

Security fixes are applied to the current `main` branch. Historical research
artifacts and third-party forks are not maintained.

## System and Scope

S3LiteNet is research software for training, evaluating, and benchmarking
lightweight anomaly-detection models. Covered components include Python source
code, model loading, dataset processing, experiment configuration,
dependencies, automation, and reproducibility tooling.

The repository is not currently a hosted inference service or multi-tenant
production platform.

## Reporting a Vulnerability

Use GitHub's private vulnerability reporting feature under **Security →
Advisories → Report a vulnerability**. Do not publish exploit details,
credentials, sensitive datasets, or unpublished research data in a public
issue.

Include the affected path, realistic attack path, impact, and minimal
reproduction conditions.

## Threat Model and Trust Boundaries

Potentially untrusted inputs include datasets, command-line arguments,
configuration values, serialized artifacts, dependency updates, and pull
requests. Important assets include host code execution, dataset
confidentiality, experiment integrity, model provenance, and published
results.

Repository-controlled model implementations are trusted only after review.
An external dataset or artifact is not trusted merely because it has a
recognized filename.

## Security Invariants

- Dynamic model loading must remain restricted to reviewed, allowlisted files
  inside the trusted model directory.
- User-controlled paths must not escape intended project or output
  directories.
- Untrusted model or dataset formats must not trigger arbitrary code
  execution through unsafe deserialization.
- Secrets, private datasets, generated bytecode, notebook checkpoints, and
  embedded repository backups must not be committed.
- Dependency and automation changes must be reviewable, least-privileged, and
  reproducible.

## Reportable Findings and Severity Context

Report arbitrary code execution, path traversal, unsafe deserialization,
credential or dataset exposure, command injection, dependency compromise, and
practical manipulation of research results across a documented trust
boundary.

Severity depends on realistic attacker control, deployment exposure, and
impact on systems, data, models, or published evidence.

## Out of Scope

Model accuracy, performance disagreements, statistical methodology, and
reproducibility defects are not security findings unless they result from a
practical security-boundary violation.

## Known Limitations

Resource exhaustion from intentionally large local experiments is expected.
It becomes security-relevant when an attacker can trigger it in an exposed or
shared deployment.
